## BUILDER-1 — One suggestion deck: the before-and-after grid deck in all three builders, and the same grid on the matched-sauces deck

Today SuggestionCardDeck (IngredientProfileCard, two FlavorGrid charts: Now and With X) is mounted only in the Recipe Notebook and always with a single card; the invent panels (InventCocktail, InventSauce, InventRecipe) show plain chips (InventSuggestions) and plain replacement lists; SauceSuggestionDeck draws the old BeforeAfterRadar twice per card. Build: (1) in each of the three invent panels, 'Goes well with what you have' keeps its chips for a quick add and gains a button, 'See how each changes the flavor', that opens SuggestionCardDeck with ALL current suggestions as cards (swipe, arrows, dots; Add on each card adds the line exactly as the chip does, amounts included). (2) The replacements ('Don't have it? Try...') open the same deck in swap mode over the stand-ins. (3) The deck's Now grid must equal the panel's own flavor profile: feed it the build's lines with amounts through the one profile calculation the panels already use (profileForRecipe / buildFlavorProfile / profilePair); if the deck today computes from names only, extend it rather than adding a second calculation, and keep its Recipe Notebook mount working. (4) SauceSuggestionDeck draws the FlavorGrid pair instead of BeforeAfterRadar; delete BeforeAfterRadar when nothing imports it. Deck opened from a panel is an overlay in the chalk look that returns to the panel where the cook was. Ingredients with no flavor data are handled as the grid already does.

## BUILDER-2 — The chalkboard recipe builder gains what only the Recipe Notebook had

InventRecipe.jsx (the chalkboard recipe builder) gains, reusing the existing components and logic rather than rewriting them: (1) the Flavor Profiles card (RecipeFlavorProfilesCard: overview ranked bars, fixed wheel, per-note pages whose Boost/Temper chips add to the build with a predicted amount, Enhance, Pairings), opened from the builder's flavor profile row; it must read the build's lines and amounts. (2) Model-based suggestions and smart swaps: the set-completion model's candidates (loadSuggestCandidates / recipeRuntime, as RecipeLabMobile uses them) join the builder's suggestion list and its deck from BUILDER-1, kitchen first, de-duplicated, with the pairing-index ranking as the fallback when the model is not loaded. (3) Find a cocktail, Need a sauce and Find wines buttons wired to the same App handlers the Notebook uses (handleFindCocktail, handleFindSauce, onFindWine), fed from the build. (4) Cooking-method chips (RecipeCookingMethod). (5) When the builder is opened from a handoff that carries method steps or a picture, they are shown (collapsed 'Method (N steps)', picture with remove) as the Notebook shows them. Do not remove anything from the Notebook in this task and do not change routes; BUILDER-3 does that. Retired on purpose and NOT to be ported: swipe-left delete, per-row match %, the focal flag, Recenter, NotebookStarter.

## BUILDER-3 — The Recipe Notebook tab opens the chalkboard builder; the paper page is retired

Tab 'recipe' and ?path=notebook mount the chalkboard recipe builder instead of RecipeLab/RecipeLabMobile. Every existing way in opens the builder seeded with that recipe: the Network panel's build recipe, Profile's load recipe, Cocktail and Sauce 'open in Recipe Notebook', the Pairing Lab's send to recipe, Make a recipe (sendToNotebook), URL import, and a handoff from an invention (inventionHandoff). The seed carries lines, amounts, title, steps, picture, and now also the dish type and cuisine that inventionHandoff drops today. With no handoff the tab opens the builder at its first question, or with the build the cook left there (keep work in progress across tab switches as the Notebook did; say how). Saving goes through saveInvention (amounts, picture, share). Recipes saved earlier by the Notebook (names only, userProfile.addRecipe) must still list in the Cookbook and Profile, open in the builder, and save without being duplicated or losing their name; do not migrate stored data in place. Unmount RecipeLab, RecipeLabMobile, RecipeNotebook and NotebookStarter (delete in BUILDER-5, not here, so this change is easy to revert). Update or replace the tests that asserted the paper page; a test that covered behaviour now retired by the spec (swipe-delete, match %, focal, recenter, starter) is removed with a line in the report naming it; any other failing test is a real regression to fix.

## BUILDER-4 — Tap an ingredient to see its card

A reusable IngredientCard overlay built on the Pairing Lab's chalk single-ingredient card (PairingModeCard with props from buildPairingCardProps in src/data/pairingCardData.js, shown for the ingredient's own profile as the Pairing Lab's peek does), not on the Network's IngredientPanel. It shows the name, taste and aroma, what it pairs with, and shared compounds where known, with 'Open in Pairing Lab', and, when opened inside a builder, 'Add to this recipe' (or 'Swap it in' from a replacement). Closes with Back, Escape and a tap outside; focus returns to the name that opened it. One provider or hook (for example useIngredientCard) so surfaces only need to render a tappable name. Make ingredient names tappable in: the three builders' lines (InventList), suggestion deck cards (IngredientProfileCard name), suggestion chips via a small info button (a tap on the chip still adds), Flavor Profiles 'Driven by' names, cocktail, sauce and wine detail cards (LabNodeCard ingredient lines and 'pairs with' chips), Cookbook recipe card ingredients, What do I need rows, shopping list rows (the checkbox must keep working; the name is the link, with a target of at least 44 px that cannot be confused with the checkbox). NOT on the public shared recipe page. While the large dataset is still loading, tapping shows a short loading state and then the card; an ingredient the app does not know (free text, an unresolved name) is not a link, or says plainly that there is no card. Names resolve through the curation aliases. Add a usage event only if the catalogue, docs table and privacy page are updated together (name only as a count, never the ingredient text).
