# invent as-built specs

## INVENT-1 — Shared build model for invent: baseline skeleton, pre-filled required slots, swap/add/remove, guard rails

New pure module src/data/inventBuild.js: Build/Slot/Line state shared by the three invent panels. seedBuild(skeleton, {pinned}) places pinned keys in the first accepting slot (locked) or in extras; fillRequired(build, rankFn) fills only empty required slots with the top-ranked pick; shortlist(build, slotId, rankFn, n) ranks candidates against the rest of the build; setSlot/clearSlot/addExtra/removeExtra are immutable; clearing a required slot reports it in `missing` instead of refilling. Guard rails (one base spirit, never two sours, no duplicate ingredient, lab-specific rules passed in) refuse a bad add with a one-line reason. Lab-agnostic: skeletons, rankFn and amounts are injected.

## INVENT-2 — Cocktail Lab invent: spirit first, then 'what are you going for?', then build the drink yourself

Rework src/components/InventCocktail.jsx onto inventBuild.js. Step 1 picks the spirit (bar's base spirits, or the codex's most common with an empty bar; 'any' allowed); step 2 picks the style from the 6 codex families, each with a one-line plain description (Sour: bright, shaken, citrus-forward; Aromatic Stirred: spirit-forward, silky; Highballs & Fizzes: long, bubbly, easy; Aperitivos: low-proof, bittersweet, bubbly; Tropical Sours: fruity, shaken, crushed ice; Boozy Sippers: strong, stirred, slow). Aperitivos with a spirit chosen says the aperitif is the base instead of dropping the pick silently. The card shows the FAMILY_SKELETONS slots with required ones pre-filled by the existing pairing score; each slot opens a ranked shortlist (bar first) plus free text; '+ add an ingredient' adds extras. Amounts (scaleAmounts), glass, build, colour, why-line and closest cocktails update on every change. Shuffle removed; Riff on it, Write it in the Recipe Notebook and Start over remain.

## INVENT-3 — Sauce Lab invent: technique (+ protein), then build the sauce yourself

Rework src/components/InventSauce.jsx onto inventBuild.js. Baseline = one of the 10 INVENT_STYLES (Roux & milk, Roux & stock, Brown reduction, Emulsion, Tomato simmer, Curry base, Stir-fry, Mole, Salsa, Nut sauce) plus an optional protein. One sauce card instead of three: required slots pre-filled from pantry first by pairStrength with the build and protein ('you'd need' kept for non-pantry picks), optional slots empty with ranked shortlists, free text and extras. 'Only what I have' restricts shortlists to the pantry and reports an unfillable required slot as missing. Amounts (amountFor), method (methodFor), wine-with-protein and closest sauce update live. Shuffle and the three-up page removed.

## INVENT-4 — Recipe Lab invent: dish type + main baseline (cuisine optional), then build the dish yourself

New pure src/data/dishSkeletons.js with 8 dish-type skeletons (stir-fry, braise/stew, soup, salad, pasta, roast, tacos, grain bowl), slot membership from the ingredient-graph categories used by recipeRoles / recipeMains.js. Rework src/components/InventRecipe.jsx onto inventBuild.js: step 1 dish type (DishArt drawings), step 2 main (kitchen proteins/legumes/veg first, any ingredient allowed), step 3 optional cuisine chips that only re-rank. Slot shortlists rank by the set-completion model (suggest, cuisine-aware, restricted to the slot's kinds) blended with the curated+everyday pairing index, kitchen first; if the model fails to load, ranking falls back to the pairing index and the panel still works. Amounts (predictBowlAmounts) and closest real recipe update live; Write it uses the existing inventionHandoff path. Shuffle and the three-up page removed.

## INVENT-5 — Search parsing for 'Invent this': split a search into recipe names and ingredients, pick a baseline

Pure parseSearchForInvent(query, {names, vocab}) in src/data/inventBuild.js: comma-separated terms (ingredientSearch.parseQuery) classified as a recipe name (codex cocktail, sauce, Cookbook recipe; exact or near match) or an ingredient (vocab), unknown terms kept as free-text extras. Baseline resolver per lab: a name gives that recipe's family/technique/dish type with its lines pre-filled (source 'search'); ingredients alone use the browse page's active chips if any, else the skeleton that locks the most search ingredients (tie: most common style).

## INVENT-6 — '✨ Invent this' button on the Cocktail, Sauce and Cookbook search bars

CocktailBrowse.jsx, SauceBrowse.jsx and CookbookLab.jsx show '✨ Invent this' whenever the search box has text, including when 0 results match ('No cocktail has gin + cucumber + chartreuse — invent one?'). ## INVENT-8 — Invent shared pieces for start-empty: checklist, category recommendation, suggestions, replacements, flavor profile, name-and-save

Shared building blocks the three panels will use; no panel is reworked here. Pure, in src/data/inventBuild.js (additive, existing API kept): openBuild({ lab, baseline, lines }) for a list with no category; applyCategory(build, skeleton) / clearCategory(build) that re-home the same lines into a skeleton's slots (or back to a flat list) without adding or dropping any; checklist(build) -> [{ slotId, label, required, done, key }]; advice(build) -> soft notes for rails that are advice not refusals (two base spirits = split base), with only a duplicate ingredient still refused; recommendCategory(keys, skeletons, { order }) -> { id, placed, requiredPlaced } | null using the best assignment of keys to distinct slots (the logic INVENT-5 used for search, moved here and reused there); suggestNext(build, rankFn, n) -> ranked candidates for the whole list. New pure src/data/inventProfile.js: buildFlavorProfile(keys, nodes) on recipeProfileAnalysis.js (scores per axis, which keys had no data). New pure src/data/inventSaved.js: the saved-item shape, toSavedItem(build, { name, category, lines, method, glass, protein }), validation (name, at least two ingredients), and fromSavedItem(item) -> a seed that reopens it. Components (lab-agnostic, chalk): InventList.jsx (the cook's lines with editable suggested amount, remove, 'don't have it' mark and a replacements popover fed by a replacementsFor(key) prop, plus the always-visible add box), InventChecklist.jsx, InventSuggestions.jsx, InventCategoryHint.jsx (recommendation with Accept / Not now), InventFlavorProfile.jsx (compact 11-axis chart reusing the recipe creator's drawing where it can), InventNameSave.jsx (empty name box, save button, disabled rules, signed-out prompt via an onNeedSignIn prop). InventSlots.jsx stays until the panels stop using it (INVENT-13 removes it).

## INVENT-9 — Cocktail Lab invent starts empty: which liquor, optional style, add your own ingredients, recommended style, suggestions, replacements, flavor profile, name and save

(optional)' is collapsed; choosing one of the 6 families shows the checklist built from FAMILY_SKELETONS; with none chosen and two or more ingredients the recommendation appears and is applied only on Accept. Amounts are suggestions by role (scaleAmounts when a style is set, role defaults otherwise), editable. The flavor profile is drawn from the list. The name box is empty; 'Add to my cocktails' calls onSave(savedItem) (wired in INVENT-12); Riff on it and Write it in the Recipe Notebook stay. fillRequired is not called anywhere in the panel. The seed prop still opens the panel from a search with the searched ingredients as the list.
