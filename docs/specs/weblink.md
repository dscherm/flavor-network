# weblink as-built specs

## WEBLINK-17 — Apple News links: find the recipe on the publisher's own site, fail helpfully, and accept ?import= from an iOS Share-sheet Shortcut

The owner's import of an apple.news link failed with apple-news-unresolvable. apple.news pages never contain the publisher's page for newer articles, but do carry the recipe title and publisher. Server (functions/src/scrape/applenewsResolve.ts): a hard-coded publisher table (name/aliases -> host, own search URL, recipe-path regex, paywalled flag, or an unsearchable reason); the publisher's OWN site search is fetched through the existing SSRF-checked fetcher with the r.jina.ai fallback (no general web search engine); candidate links must be on the publisher host and match a recipe path; a candidate is accepted only if its slug AND then the parsed page's recipe title both match the Apple title (identity tokens, coverage >= 0.85 and Dice >= 0.85, >= 2 shared words, marketing adjectives kept, ties refused as ambiguous). Resolution is capped at 12 s and at what is left of a 23 s overall budget (client races 25 s, callable times out at 30 s). Success returns a normal result plus resolvedFrom 'apple.news', publisherUrl and publisherHost; the older canonical-link path (which DOES fire on older Bon Appetit and Allrecipes articles) is tagged the same way. Failure returns appleNews {title, publisher, paywalled, searchQuery, reason, publisherUrl?}. Client: src/components/AppleNewsFallback.jsx replaces the dead-end message (recipe + publisher named, why, subscriber-only when true, a user-clicked 'Find it on the web' search link, a paste box, the Share -> Open in Safari tip); the preview says 'Found on <host>'. ?import=<url> (and ?path=make&import=) opens Make a recipe on the web-link step and queues the parse through the existing signed-out flow; only http(s) is accepted (src/utils/importParam.js) and the param is removed with history.replaceState. Shortcut steps: docs/apple-news-shortcut.md, linked from a 'Sharing from Apple News?' expander.
