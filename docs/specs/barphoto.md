## BARPHOTO-3 — scanBar Cloud Function for invite-code holders: photo in, bottle list out, on the owner's own (free) key

Owner rulings 2026-11-14, in order: 'No paid key'; 'Each user brings a key'; then 'Stick with pasting their own key but also allow users that have a code from me to use my key'. So there are two ways to scan: a user's own key in the browser (BARPHOTO-6), or a code the owner hands out, which runs the scan on the owner's key through this function. Start from the function already built on branch worktree-agent-ac7124b4a03455f73 (commit c96f7a9, functions/src/barscan/, 33 tests) and change the access rule: instead of requiring sign-in, the request carries `code`; the function looks up Firestore `scanCodes/{code}` ({ enabled: boolean, label: string, dailyCap?: number }) through the Admin SDK and refuses a missing, unknown or disabled code with permission-denied and one fixed message (never saying which). Codes are compared as given after trim; a code must be 8-64 characters of [A-Za-z0-9-] or it is refused before any lookup. Usage is counted per code per UTC day (`barScans/{code}_{day}`), default cap 10, overridable per code by dailyCap; over the cap is resource-exhausted. Everything else stays: input validation, 4 MB limit, hardened prompt with no stated maximum, retries inside 25 s, no retry on a daily-quota 429, lenient parse, truncation to 60, no image or code in logs (log the code's label, not the code). The key is the GEMINI_API_KEY Functions secret; the owner's key is on Gemini's free tier (about 20 requests a day in total), so the 'out of capacity for today' message matters. firestore.rules must deny all client access to scanCodes and barScans. Add a short docs section on how the owner creates, disables and caps a code in the Firebase console. Merge the branch into master when green.

## BARPHOTO-4 — My bar: 'Add from a photo' with an invite code or the user's own Gemini key, and a review list before anything is added

src/components/MyBarPanel.jsx gains '📷 Add from a photo' (file input, image/*, camera or library). First use shows a one-time set-up card with two choices. 'I have a code': a paste box; the photo is read using the app owner's Google key, through this app's server, and is not stored. 'Use my own Google key': what the key is, that it is free, a link to Google AI Studio's key page, a paste box, 'the key stays on this device and is sent only to Google', that the photo goes from the browser straight to Google under the user's own key and Google's terms for that key apply, and that a free key allows about 20 scans a day. Change / remove is always available. New src/components/BarScanReview.jsx: one row per bottle (label, 'added as' name editable with the bar typeahead, checkbox; high confidence checked, medium/low unchecked; 'already in your bar'), non-alcohol items offered for the shared kitchen unchecked, 'Add N to my bar', 'Add another photo'. Uses src/data/barScan.js (BARPHOTO-6) for storage, the downscale, the scan and the row mapping; the code path uses httpsCallable(functions, 'scanBar'). Guidance line 'One shelf at a time, labels facing you'; plain messages for a rejected key, a rejected code, the daily limit, offline, busy and an empty result; manual search always still usable. No sign-in is required.

## BARPHOTO-6 — Bar photo scan client: the user's own Gemini key in the browser, or an invite code through scanBar

Owner rulings 2026-11-14, in order: 'No paid key'; 'Each user brings a key'; then 'Stick with pasting their own key but also allow users that have a code from me to use my key'. New module src/data/barScan.js, no React. (1) Storage on this device only, wrapped like myBar.js so blocked storage means 'nothing saved', never an error: the user's own key ('fn-gemini-key') and an invite code ('fn-scan-code'); load/save/clear for each, a format sanity check, a mask for display, and scanMode() -> 'key' | 'code' | null (own key wins when both are saved). (2) downscaleSize(w, h, 1600) and a canvas-based downscale to JPEG. (3) scanBarPhoto({ imageBase64, mimeType, vocab, key?, code?, fetch, callScanBar }): with a key it calls Google's generateContent REST endpoint directly from the browser, key in the x-goog-api-key header (never in the URL), model gemini-2.5-flash, temperature 0.1, JSON response schema, thinking off, capped output tokens, prompt and schema as in functions/src/barscan/handler.ts (only readable labels, never another brand's name, key '' when nothing fits, no stated maximum, truncate to 60 in code), retries 503/429 up to 3 times inside 25 s but not a daily-quota 429; with a code it calls the scanBar callable (injected as callScanBar) with { code, image, mimeType, vocab } and maps its HttpsError codes. Both paths return the same { bottles, other } and the same typed errors: not-set-up, bad-key, bad-code, daily-limit, busy, offline, unreadable. (4) toReviewRows(result, bar, { names, roles }) with barKey/isBooze: default checks by confidence, already-in-bar flag, bottles with no bar name kept as editable rows, merge of a second photo without duplicates. The vocab list is built from the cocktail codex the way scripts/measureBarPhoto.mjs does. fetch and callScanBar are injected so tests use no network.
