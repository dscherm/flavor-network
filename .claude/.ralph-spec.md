## Goal

Ship a 4-tier hierarchical **flavor graph** (Aroma → Taste → Mouthfeel → Adjective leaves) for the entire ingredient corpus, plus re-color the 3D network by flavor category, plus derive 2D layout positions from the 3D GNN vectors — all as **one bundled Phase-1 delivery (1 week)**. Phase 2 (1.5 weeks, follow-up) adds quality-bump verification (held-out cross-check + chef walkthrough). The graph is consumed simultaneously by three user-facing surfaces: IngredientPanel display, 3D network re-color, and a new filter-axis pill — landed together so the chef-user experiences the richer model end-to-end on day one.

### Key tree-shape decisions (locked across R1–R6)

- **Graph, not strict hierarchy.** Leaves can attach to multiple Tier-3 nodes. A leaf like "caramel" can sit under (woody → sweet → sticky) AND (fruity → sweet → sticky). JSON shape = edge-list, not nested. Per R2.
- **Multi-parent at T2 and T3 too.** Mint sits in `green` (Tier-1) but carries BOTH `bitter` and `astringent` at Tier-2 and BOTH `cooling` and `pungent` at Tier-3. Per R3.
- **Tier-aware terms.** The same English string can appear at multiple tiers with different semantics. Specifically: **pungent at Tier-2** = chemoreceptor activation (chili / garlic / mustard "taste" signal); **pungent at Tier-3** = lingering nasal/cavity sensation (menthol / eucalyptus mouthfeel). UI must render a **TierBadge** so the user can disambiguate. Per R4.
- **`BRISCIONE_TASTE` is NOT modified.** Pungent stays in the 8-term Tier-2 taste palette; the Tier-3 vocabulary is additive. No breaking change to shipped palettes, color maps, or threshold tables. Per R4.

### The 4 deliverables (all Phase-1)

1. **Flavor graph schema + data**. New file `public/proDataset/flavor_graph.json` with edge-list shape:
   ```json
   {
     "ingredients": {
       "<name>": {
         "tier1_aroma": ["green"],
         "tier2_taste": ["bitter", "astringent"],
         "tier3_mouthfeel": ["cooling", "pungent"],
         "leaves": ["menthol", "fresh", "sharp", "grassy", "herbaceous"]
       }
     },
     "vocabulary": {
       "tier1_aroma": ["fruity", "floral", "green", "woody", "spicy", "fatty"],
       "tier2_taste": ["sweet","sour","bitter","salty","umami","pungent","astringent","spicy"],
       "tier3_mouthfeel": ["cooling","pungent","creamy","crispy","chewy","sticky","crisp", "..."],
       "leaves": ["menthol","fresh","sharp","grassy","herbaceous","caramel","mineral","rancid","..."]
     },
     "edges": [
       {"from": "green", "to": "bitter", "tier": "1to2"},
       {"from": "menthol", "to": "cooling", "tier": "leaf-to-3"},
       {"from": "menthol", "to": "fresh", "tier": "leaf-to-leaf?"}
     ]
   }
   ```
   Exact edge schema is up to the implementer; the contract is "graph, not nested tree, with multi-parent leaves."

2. **Network node re-color**. The 3D Flavor Network's node colors are driven by **primary Tier-1 aroma** (when an ingredient has multiple Tier-1 entries, the primary is the one with the highest GNN aroma-head probability above its calibrated threshold). Cluster centroids inherit the dominant member's Tier-1 color. The existing `BRISCIONE_AROMA` palette drives the colors — no new palette needed.

3. **2D-from-3D positions**. Extend `flavor-gnn/scripts/flavor_layout_v2.py` to dump a parallel `flavor_positions_2d.json` at `n_components=2` (same UMAP seed, same input vectors). The 2D Pairings mode (currently using cooccurrence layout) gains a `flavor2D` variant that reads from this new file. Toggle is part of `MODE_CYCLE` or accessed via URL param (TBD by implementer).

4. **IngredientPanel display + Filter axis**. The IngredientPanel renders the per-ingredient graph as a tree-view / chip-cloud (UI shape TBD by designer/implementer — could be nested chips, accordion sections, or a small wedge diagram). A new filter pill ("flavor category" or similar) is added alongside the existing aroma/taste/season/cuisine pills; filtering by a Tier-1/2/3/leaf term highlights matching ingredients in the network.

## Defined Variables

### Mint canonical fixture (locked, R3+R4)

```js
flavorGraph.ingredients['mint'] = {
  tier1_aroma:      ['green'],
  tier2_taste:      ['bitter', 'astringent'],
  tier3_mouthfeel:  ['cooling', 'pungent'],          // pungent here = Tier-3 mouthfeel sense
  leaves:           ['menthol', 'fresh', 'sharp', 'grassy', 'herbaceous'],
};
```

### Hybrid classification (R3 preview, locked R6)

- **Tier-1 (aroma)** + **Tier-2 (taste)**: **GNN-derived** for every ingredient where `gnnProbs` is available. For each ingredient, take every aroma + taste head where `prob ≥ calibrated_threshold` (from `odor_thresholds.json`). When the GNN is missing (≈1,123 ingredients with no prediction, per `chemDataset-status`), fall back to curated `node.taste` / `node.aromas` strings if present, else leave empty.
- **Tier-3 (mouthfeel)**: **Manual curation for top-500 ingredients** (curated by chef-user). **Rule-derived for the long-tail 3,400+** via lookup table on `gnn_compounds.json` Level-2/Level-3 descriptors (project memory: `project_gnn_compounds_level2_descriptors` — 206 tags across 3,283 ingredients).
- **Leaves**: **Manual curation for top-500**. Long-tail leaves are **rule-derived** from the same Level-2/3 descriptor lookup table; many ingredients will have 0 leaves, which is fine. The vocabulary is informed by Mosaic Flavors' 100-term guide but NOT copied verbatim — chef-user curates a subset matching the project's palette.

### Re-color primary-path selector (R1 follow-up)

When an ingredient has multiple Tier-1 aroma entries (e.g. caramel with `[woody, fruity]`):
- The **primary Tier-1** is the one with the **highest GNN aroma-head probability above its calibrated threshold**.
- The network node's color comes from `BRISCIONE_AROMA[primary_tier1]`.
- Tie-break (probabilities equal within ε=0.01): use the order declared in `AROMA_AXES = ['fruity', 'floral', 'green', 'woody', 'spicy', 'fatty']` — first-match wins.

## Constraints

### Visual

- `BRISCIONE_TASTE` (sweet/sour/bitter/salty/umami/pungent/astringent/spicy) — **unchanged**. No breaking change to existing palettes.
- `BRISCIONE_AROMA` (6 terms) — **unchanged**. Used for network re-color.
- Tier-3 mouthfeel palette — **new**, but NOT a single color map; mouthfeel terms are display-only at the panel level (chip text, optional tier-3 icon). They do not drive node colors.
- Leaves — display-only as text chips; no color contract.
- **TierBadge** required wherever a Tier-2/Tier-3 dual-tier term is rendered (currently: only "pungent"). Implementation choice: small superscript tier number, or a pill-color shift, or both. Honest disambiguation is the binding gate.

### Brownfield reuse

- `flavor_layout_v2.py` already produces 3D positions — extend it (not fork) to also dump 2D.
- `gnn_compounds.json` already loaded by `useProData` — the rule-derived long-tail lookup runs in this hook at load time (or offline-baked into `flavor_graph.json`).
- `BRISCIONE_AROMA` + `BRISCIONE_TASTE` color maps consumed by IngredientPanel + WedgeGridFlavorWheel — both can render the new graph data without new color tables.
- `odor_thresholds.json` is the per-task calibration source for GNN-derived Tier-1/Tier-2.

### Performance

- `flavor_graph.json` size estimate: ~600KB raw / ~80KB brotli (15 entities per ingredient × 3,913 ingredients × ~10 byte JSON tokens). Acceptable.
- No GNN retraining required.
- No new offline build beyond extending `flavor_layout_v2.py`.

### A11y

- TierBadge has accessible label: `"Tier-2 taste"` vs `"Tier-3 mouthfeel"` so screen readers disambiguate.
- The IngredientPanel tree-view exposes structure semantically (nested lists with role="group", or equivalent).

## Risks / Notes for Executor

1. **Tier-3 long-tail accuracy is the biggest unknown.** Rule-derived from `gnn_compounds.json` is the cheapest path but quality varies. Phase 2 cross-check + walkthrough are specifically designed to catch this — accept that Phase 1 ships with some tier-3 noise for the long-tail.

2. **Pungent dual-tier is a foot-gun.** Implementer MUST surface tier context in the renderer; rendering `"pungent"` bare in two places (Tier-2 chip and Tier-3 chip for the same ingredient) without a TierBadge is the most likely user-confusion source. Use distinct visual treatment.

3. **Network re-color is potentially destabilizing.** Today's cluster colors carry visual identity ("the dairy cluster is white-ish, the protein cluster is reddish"). After re-color by Tier-1 aroma, dairy ingredients with `fatty` Tier-1 become orange-ish per `BRISCIONE_AROMA`. Some chef-users may push back. The Phase-1 coverage AC doesn't gate on chef approval — schedule a soak day BEFORE running phase 2 walkthrough.

4. **2D-from-3D may not look meaningful.** UMAP at `n_components=2` on the same vectors that produce the 3D layout will have a different topology — clusters that are well-separated in 3D may overlap in 2D. The deliverable lands the JSON regardless; whether the 2D mode becomes the user's default 2D view is a separate UX decision.

5. **Vocabulary curation is the chef-user's bottleneck, not the executor's.** Top-500 manual curation requires chef-user time. The executor can scaffold the curation file (CSV with ingredient + empty tier columns) but the chef-user must fill it. Block early to avoid Day-2/3 stall.

6. **Mosaic's 100 terms is inspiration, not contract.** Curated leaf vocabulary will likely be 30–50 terms tuned to the project's palette. Use Mosaic's framework for thinking, not for vocabulary copy-paste.
