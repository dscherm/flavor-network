# chemDataset — Current Status (as of 2026-04-26, v3 milestone)

Injected into every Claude Code session via `CLAUDE.md` @-include.

## Active model
- **M3 multi-task MPNN v3** (GINEConv, 3 layers, hidden=128), 5-fold CV, 15 epochs, batch=64, seed=42, CPU.
- Trained on **19,902 unique-SMILES compounds** (≈4× the R10-63 corpus) with **per-task label masking** so each source only contributes signal to the heads it actually measures.
- Loss: BCE + per-task `pos_weight` computed over masked-in (observed) elements only.
- Active artifact: `flavor-gnn/artifacts/m3_multitask.pt` (also snapshotted at `m3_multitask_v3.pt`).
- CV / calibration artifacts: `cv_results.json` + `cv_results_v3.json`, `threshold_calibration.json` + `threshold_calibration_v3.json`.
- R10-63 baseline preserved at `*_R10-63.json/.pt` for rollback.
- Output consumed by app: `public/proDataset/gnn_entropy.json` (per-ingredient probs + entropy), `public/proDataset/gnn_compounds.json`, `public/proDataset/gnn_positions.json`.

## Coverage
- 2,790 ingredients have GNN predictions (unchanged — bottleneck is the ingredient-level pairing graph, not the molecular model).
- 1,123 of 3,913 (29%) ingredients have no odor prediction — skewed toward high-pairing hubs (nut, cheddar, bacon, egg, mayonnaise, vegetable oil, tomato paste, etc.).
- ~56% of pairings have both endpoints scored. ~34% of strong pairings (strength ≥ 0.5) have a dominant shared odor class above 0.2.

## Known issues & root-cause update
- **Salty plateau confirmed (v3).** Despite expanding to 56 positives (3.5×
  vs R10-63's 16), calibrated F1 sits at 0.33. This matches the FART paper's
  finding (NPJ Sci. Food 2025): salty taste is mechanism-bound to ionic
  dissociation in the food matrix and is not reliably predictable from
  molecular structure alone. FART explicitly excludes salty from its
  classifier for this reason. **Do not surface salty in the UI under any
  threshold.** No more data ingestion will fix this — the next attempt would
  need to model the matrix context, not just the SMILES.
- **odor_spicy still weak.** F1=0.33 calibrated. Same root cause — capsaicin/
  piperine-style spice mechanisms are TRPV1-mediated and the structural
  signal we have is sparse (196 train positives). Surface only with a
  conservative threshold.
- **Threshold collapse (R12 diagnosis, still relevant):** rare tasks emit
  confident positives only at p > 0.85–0.95. Per-task calibration recovers
  F1 by sweeping thresholds. v3 confirms this — calibration thresholds
  for umami/sour/salty all land at 0.80–0.90.
- **Hub gap.** The training subset excludes top-pairing hub ingredients,
  reducing coverage where users most frequently look. Still stands.
- **Duplicate cluster labels.** Fixed in R11.

## v3 milestone — database expansion + label masking (2026-04-26)

Two-stage intervention to lift the weak heads (umami, salty, sour) without
changing the model architecture or loss function.

### Stage 1: data ingestion
- Bumped ChemTastesDB v1 → v2.1 (+905 compounds; umami 170→220, sour 33→49,
  bitter 1,400→1,565, sweet 1,180→1,205). Also fixed a latent dedup bug
  where multi-row label evidence for the same compound was being
  overwritten under PubChem CID keying.
- Added FartDB (14,563 compounds; 1,513 net-new sour positives from IUPAC
  pKa data; ~9.5k sweet, 1,695 bitter, 62 umami; salty excluded by design).
- Joined parquet expanded from ≈5,000 → **19,902 unique-SMILES compounds**.

### Stage 2: per-task label masking
First-pass training on the expanded data **regressed** bitter (-0.20) and
all six odor heads. Root cause: rows from sources that don't measure a
given task (e.g. FartDB has no odor data, BitterDB measures only bitter)
were being treated as informed-zero across all 11 tasks. The model
correctly learned "FART-like compounds have no odor" — which is wrong.

Fix: added `mask_<task>` columns to `compounds.parquet`. mask=1 only when
some source explicitly informs that label.
- FlavorDB profile rows → masks all 11 (profile is comprehensive).
- ChemTastesDB rows → masks 5 tastes only.
- BitterDB rows → masks bitter only.
- SuperSweetDB rows → masks sweet only.
- FlavorNet rows → masks 6 odors only.
- FartDB rows → masks **only the specific taste FART labeled** (a "sweet"
  row doesn't observe bitter, since FART's classifier picks one taste).
  "undefined" rows mask the 4 GPCR-mediated tastes (sweet/bitter/sour/
  umami) but not salty (FART excludes salty).

The training loss multiplies BCE elementwise by mask before reduction.
pos_weight is computed over masked-in elements only. Calibration also
restricts threshold sweeps to mask=1 rows.

### Result
- **Sour: 0.49 → 0.819 calibrated (+0.33)** — biggest single-task lift in
  the project.
- **Sweet: 0.56 → 0.904** — near-saturation.
- **Umami: 0.61 → 0.731 (+0.12)** — finally shippable with confidence.
- **All 5 odor heads beat baseline** by +0.02 to +0.10.
- **Bitter: 0.81 → 0.799** — fully recovered (the principled FART
  label-specific masking removed the artificial-sweetener distribution
  shift that caused the v2 regression).
- **Salty plateau confirmed** at 0.33 calibrated. Will not lift via more
  data; structural-mechanism issue. Drop from UI.

### Negative finding
- SMILES enumeration augmentation (random non-canonical SMILES via RDKit
  `MolToSmiles(mol, doRandom=True)`) does **not** apply to GINEConv. The
  technique works for SMILES-string-input models like ChemBERTa where each
  variant is a distinct sequence; for our permutation-invariant graph
  model, all SMILES of a given molecule produce identical graphs. Don't
  reach for this lever again without first switching the encoder.

## R12 follow-up — focal loss tested 2026-04-26 (NEGATIVE RESULT, do not retry)

Hypothesis: focal loss (γ=2) would lift `odor_spicy` (raw F1 0.236) and
`odor_floral` (raw F1 0.326), the two weakest tasks under BCE+pos_weight.

Method: 5-fold CV + full-train + per-task threshold calibration on a
focal-trained checkpoint (`m3_multitask_focal.pt`). Same data, same
splits, same model, same calibration grid as the BCE pipeline. Results
in `flavor-gnn/artifacts/cv_results_focal.json` and
`flavor-gnn/artifacts/threshold_calibration_focal.json`.

Outcome: focal **regresses** on 9 of 11 tasks after calibration.

| task | BCE cal F1 | Focal cal F1 | Δ |
|---|---|---|---|
| salty | 0.40 | 0.55 | +0.15 |
| odor_fruity | 0.62 | 0.65 | +0.03 |
| sweet | 0.56 | 0.55 | -0.01 |
| sour | 0.49 | 0.47 | -0.02 |
| bitter | 0.81 | 0.78 | -0.03 |
| odor_woody | 0.52 | 0.48 | -0.04 |
| odor_green | 0.56 | 0.50 | -0.06 |
| odor_floral | 0.46 | 0.40 | **-0.06** |
| odor_spicy | 0.30 | 0.23 | **-0.07** |
| odor_fatty | 0.52 | 0.44 | -0.08 |
| umami | 0.61 | 0.52 | -0.09 |

Mean calibrated F1: **BCE 0.530, Focal 0.504, delta -0.027**.

Root cause: focal loss softens output probability distributions by
design (downweights easy examples). The per-task threshold sweep that
makes BCE shine — pushing umami/sour/salty thresholds to 0.85-0.95 to
isolate the model's confident positives — has nothing to grip on
softer focal probabilities. Raw F1 at thr=0.5 favored focal because it
penalized BCE's hard predictions for being uncalibrated, but with
calibration BCE is strictly better.

**Decision: keep BCE. Do not retry focal/focal variants without changing
the data first.** The shipped model is at the optimum given the
loss-function lever for the current dataset. Future improvement
requires either more labeled compounds for the weak heads (197 spicy /
46 floral test positives is the binding constraint, not the loss
function) or moving to a "predicted from components" badge for compound
foods so the UI can express GNN uncertainty rather than the model
trying to pretend confidence.
